# Data Setup

The Kickstarter dataset is stored in the team's Google Drive rather than committed to GitHub.

The project uses a two-stage local data workflow:

1. **Raw data** is downloaded from Google Drive and stored locally in `data/Raw-data/`.
2. **Processed data** is created during cleaning and feature engineering and stored separately in `data/Processed-Data/`.

This keeps the original dataset unchanged while allowing the team to create reproducible cleaned and modeling datasets.

## Google Drive location

The Kickstarter dataset is stored in the team's Google Drive:

```text
1C-Kickstarter-recommendation-engine/
└── Raw-data/
    ├── DSI_kickstarterscrape_dataset.csv
    └── DSI_kickstarterscrape_dataset.zip
```

The CSV file used by the project is:

```text
DSI_kickstarterscrape_dataset.csv
```

The ZIP file is the original downloaded archive. The Python data pipeline uses the CSV file.

## Local data structure

After downloading the dataset, your local project should look like:

```text
data/
├── Raw-data/
│   └── DSI_kickstarterscrape_dataset.csv
├── Processed-Data/
├── Data_setup.md
└── README.md
```

### Raw-data

`data/Raw-data/` contains the original dataset downloaded from Google Drive.

**Do not modify the raw dataset directly.**

### Processed-Data

`data/Processed-Data/` contains datasets created after cleaning, preprocessing, or feature engineering.

Processed datasets should be generated by the project's notebooks rather than manually edited.

Both raw and processed dataset files are excluded from GitHub.

## Download the dataset

### 1. Set up the Python environment

From the project root:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

If you already have the project virtual environment set up, activate it instead:

```bash
source .venv/bin/activate
```

## 2. Set up Google Drive credentials

Ask a team member for the project's Google Cloud OAuth `credentials.json` file.

Place `credentials.json` in the project root:

```text
project-root/
├── credentials.json
├── utils/
├── data/
└── ...
```

**Do not commit `credentials.json` to GitHub.**

## 3. Configure environment variables

Create a `.env` file in the project root:

```env
GOOGLE_DRIVE_DATA_FOLDER_ID=<Raw-data folder ID>
GOOGLE_DRIVE_DATA_FILE_NAME=DSI_kickstarterscrape_dataset.csv
```

`GOOGLE_DRIVE_DATA_FOLDER_ID` should contain the ID of the Google Drive `Raw-data` folder.

Do not commit `.env`.

## 4. Authenticate and download

From the project root, run:

```bash
python3 utils/get_google_drive_data.py
```

The script will automatically create the local `data/Raw-data/` directory if it does not already exist.

On the first run, Google will open a browser window for OAuth authentication. After successful authentication, a local `token.json` file will be created.

The script searches the configured Google Drive `Raw-data` folder for the CSV and downloads it to:

```text
data/Raw-data/DSI_kickstarterscrape_dataset.csv
```

You do not need to manually create the `Raw-data` directory.

## 5. Verify the download

You should see output similar to:

```text
Found file: DSI_kickstarterscrape_dataset.csv
Downloaded file to: .../data/Raw-data/DSI_kickstarterscrape_dataset.csv
```

You can also verify that the file exists:

```text
data/
└── Raw-data/
    └── DSI_kickstarterscrape_dataset.csv
```

The downloaded dataset is intentionally excluded from Git with `.gitignore`.

## Using the dataset in notebooks

The initial data exploration notebook should load the raw dataset from:

```python
data_path = "../data/Raw-data/DSI_kickstarterscrape_dataset.csv"

df = pd.read_csv(data_path)
```

The project notebooks are organized by stage:

```text
notebooks/
├── 01_load_and_explore_data.ipynb
├── 02_clean_data.ipynb
├── 03_feature_engineering.ipynb
└── 04_modeling.ipynb
```

### Notebook workflow

**`01_load_and_explore_data.ipynb`**

Loads and explores the raw dataset. This includes checking:

* Dataset dimensions
* Column names
* Data types
* Missing values
* Duplicate rows
* Descriptive statistics
* Target distribution
* Initial data-quality issues

**`02_clean_data.ipynb`**

Handles data-quality issues such as:

* Missing values
* Invalid values
* Outliers
* Inconsistent data

The cleaned dataset should be saved separately under:

```text
data/Processed-Data/
```

**`03_feature_engineering.ipynb`**

Creates the features used for modeling, including:

* Categorical transformations
* Numerical normalization or standardization
* Non-leaking interaction features

**`04_modeling.ipynb`**

Uses the processed dataset for:

* Train/test splitting
* Baseline modeling
* Model evaluation
* Model comparison

## Important data workflow rules

### Do not modify raw data

The file in:

```text
data/Raw-data/
```

should remain an unchanged copy of the dataset downloaded from Google Drive.

If cleaning is necessary, perform the cleaning in a notebook and save the result to:

```text
data/Processed-Data/
```

### Do not commit datasets

Dataset files are excluded from GitHub through `.gitignore`.

Do not force-add dataset files with:

```bash
git add -f
```

The repository should contain the code and documentation needed to reproduce the data pipeline, not the dataset itself.

### Keep preprocessing reproducible

Whenever a data-cleaning decision is made, document the decision in the appropriate project documentation so that other team members can reproduce the same preprocessing steps.

## Files used for Google Drive integration

* `utils/google_drive_client.py` handles Google Drive OAuth authentication.
* `utils/get_google_drive_data.py` finds and downloads the dataset.
* `.env` stores local configuration.
* `.env.example` provides the expected environment-variable structure.
* `credentials.json` contains the local Google Cloud OAuth client credentials and must not be committed.
* `token.json` stores the local OAuth authentication token and must not be committed.

## Troubleshooting

### Authentication fails

Make sure:

1. Your Google account has access to the team's Google Drive data.
2. Your Google account is authorized as a test user for the Google Cloud OAuth application.
3. `credentials.json` is in the project root.
4. Your `.env` file is in the project root.
5. `GOOGLE_DRIVE_DATA_FOLDER_ID` is the ID of the correct Google Drive `Raw-data` folder.
6. `GOOGLE_DRIVE_DATA_FILE_NAME` exactly matches the CSV filename.

### The dataset cannot be found

Verify that the Google Drive folder contains:

```text
DSI_kickstarterscrape_dataset.csv
```

and that the folder ID in `.env` points to the `Raw-data` folder rather than the parent project folder.

### The download works but the notebook cannot find the file

Make sure the notebook uses:

```python
data_path = "../data/Raw-data/DSI_kickstarterscrape_dataset.csv"
```

and that the notebook is located in the project's `notebooks/` directory.

## Security

The following files contain credentials or local configuration and must never be committed:

```text
.env
credentials.json
token.json
```

The project's `.gitignore` is configured to exclude these files as well as local dataset files.
